# 和声分析知识库 Roadmap

## 目标

把"听一首歌、抠出里面的和声手法"这件事，从一次性的手工分析，变成可积累、可跨歌曲搜索对比的知识库。

**核心判断**：先把标准（词表 + 数据格式 + 分析流程）打磨稳，再决定要不要投入检索/学习功能的开发——
不要上来就堆材料，也不要上来就搭系统。标准没稳定之前搭的 UI/索引大概率要返工。

## 现状（2026-07-26）

- 已经手工分析了一首：《特别的人》（方大同），产出 [chord-analysis-special-person.html](chord-analysis-special-person.html) +
  Song Loop 里完整的和弦/旋律/段落标注
- 词表审计完成第一轮：[harmony-technique-tags.md](harmony-technique-tags.md)，发现 3 个现有文档没覆盖的
  手法缺口（变格式收尾、属和弦改道不解决、留白/不弹）

## 五个阶段

### 阶段 0 — 词表标准化 [进行中]

- [x] 审计《特别的人》用到的手法，对照三份现有和声文档（和弦进行入门/和声进阶/调性和声地图），
      产出 [harmony-technique-tags.md](harmony-technique-tags.md)
- [ ] 缺口手法（`plagal-ish-ending` / `dominant-misdirection` / `tacet`）攒够第二首歌的独立例子后，
      再决定是否正式写回对应的 harmony 文档

### 阶段 1 — 数据格式标准化 [未开始]

- [ ] 定义"手法实例"的最小字段集（歌曲、小节范围、标签、涉及和弦、简短说明、旋律证据），
      跟展示层（HTML 分析页）解耦——数据是底层、页面是展示，不要耦合在一起写
- [ ] 先不做检索 UI，只是把格式定下来

### 阶段 2 — 分析流程标准化 [未开始]

- [ ] 把《特别的人》这次的流程写成可复用 checklist：
      素材库传 mp3 → Song Loop 手动敲和弦 → （若有谱）核对简谱旋律 → 疑点用旋律交叉验证 → 按阶段 0 词表打标签
- [ ] 明确"没有 PDF 简谱的歌"怎么办——大部分歌不会像《特别的人》这样刚好有一份带简谱的弹唱谱，
      需要一个不依赖现成谱面的备用做法（比如直接在 Song Loop 里手动记录音高）

### 阶段 3 — 试点 2-3 首风格差异大的歌 [未开始]

- [ ] 挑选原则：故意选跟《特别的人》和声语言不一样的歌，用来压力测试词表和数据格式撑不撑得住
- [ ] 每首都走一遍阶段 0-2 的流程，回头修阶段 0/1 里绷不住的地方（新手法、标签模糊、字段不够用）

### 阶段 4 — 决定要不要做检索/学习功能 [未开始，取决于阶段 3 结果]

- [ ] 试点稳定之后再评估：搜索/索引 UI 值不值得做
- [ ] 要不要加一个自测/回想环节（比如"这条进行用了什么手法"），让它是真正的"学习"而不是一个只能翻的百科页
