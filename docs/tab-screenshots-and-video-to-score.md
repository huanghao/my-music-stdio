# 把教学视频里的谱面变成整齐的谱子（截图 / 视频两种做法）

教学视频里的谱面常常是翻页的横向谱条，一页只有 4~5 个小节，要一页一页看。
这里记录把它整理成"每行 4 小节、两端对齐"的 PDF 的方法，以及放进 Licks 时要注意的事。
可运行的脚本和逐步命令在 [`experiments/tab-stitch/`](../experiments/tab-stitch/README.md)；这篇只讲思路、取舍和已知限制。

首个实例：《At The Place Where You Call》solo（48 小节，B 站 `BV1PH4y1N7Vr`）。截图版和视频版得到一致的结果。

## 核心思路

不做识谱（OMR）：谱面像素本来就是正确的，只做**裁剪、对齐、拼接、重新排版**。这样音符和指法不会出错，代价是被遮挡的像素恢复不了。

1. **归一化**：每张图/每一页的缩放比例都不同（谱线间距 21~37px），先找 6 条谱线、把间距缩放到 32px，第 1 线对齐到固定高度。之后所有操作都在同一尺度上。
2. **按小节线切**：谱线区内某列几乎全黑、并且谱线下方没有墨迹（符干会向下延伸，小节线不会）的列就是小节线。小节号标签居中压在小节线上，所以每个小节左右多切 20px，相邻小节在共享小节线处用"取较暗像素"合并，数字和小节线都完整。
3. **拼被截断的小节**：一页的最后一个小节常常只露出一半，下一页的开头是它的后半。用重叠区做相关性（NCC）求位移，必要时带 ±3% 缩放微调。重叠只有几十像素甚至没有，匹配度低于 0.7 就按"没有重叠"处理，留空白并提示人工确认（这次只有第 17 小节，确认没漏内容：它本来就是 4 拍，只是长音后面的空白）。
4. **重新排版**：每 4 小节一行；为了让每行两端对齐，在"除谱线外整列都没有墨迹"的空白处按比例插入空白列加宽，字符不拉伸；比目标宽度还宽的行整体缩小（最多约 13%）。A4 横向，每页 4 行。

## 从视频自动取谱

比手工截图更好，因为画面干净、可以自动去重：

- 只读画面下半部分的谱区（2fps 即可），有大面积浅色背景才算有谱，片头和口播自动跳过。
- 谱面翻页显示，同一页会停留几十秒，老师还会反复讲同一段：按墨迹内容分组，重复的页合并，合并时逐像素取最亮值，**蓝色播放头**（半透明、一直在扫）就消失了。比较重复页时要容忍 1~2px 垂直抖动，否则同一页会被误当成新页。
- 页面顶端偶尔会漏进吉他画面和字幕，比较时忽略最上面 56px，该页顶端再涂白。
- 水印：B 站水印只出现在用户自己的截图里，视频本身没有。截图版需要手工框出水印并擦除，盖住的符杠/符干会有缺口；视频版没有这个问题。
- 小节顺序没有做 OCR，靠"按视频时间首次出现的顺序 + 相邻页对齐"得到。老师如果跳着讲，顺序可能不对，要看日志里的匹配度。

## 容易踩的坑

- 小节线检测漏掉"带圈的尾音"：符干和小节线连在一起，被"下方没有墨迹"的条件排除。
- 对齐时必须屏蔽谱线下方（符杠、水印、三连音括号）。没有真正重叠时，NCC 的最大值会出现在"重叠最小"的位置，是假峰值。
- 比较行宽的第一版只统一了谱线大小，右边参差不齐；说"对齐了"之前要真的看输出图。
- 中文字体：PIL 画中文用 `STHeiti Medium.ttc`，`PingFang.ttc` 会变成方块。

## 工具

没有 Homebrew（Intel Mac 已不再支持），装在独立的 conda 环境里，软链到 `~/.local/bin`（和 `gh`、`bat` 的做法一致）：

```bash
# ffmpeg、ffprobe、yt-dlp  →  ~/.local/share/cli-tools/media
~/miniforge3/bin/conda update -p ~/.local/share/cli-tools/media -c conda-forge --override-channels --all   # 升级
```

下载 B 站视频：`yt-dlp --cookies-from-browser chrome`（读 Chrome 里的登录状态，能拿到 1080p）。
B 站是音视频分开的，要同时下 `-f 30080`（1080p H.264 视频）和 `-f 30280`（166k AAC 音频），再 `ffmpeg -c copy` 合并；
只下画面（`-f 30080`）做谱子够用，但**没有声音**。

## 放进 Licks 时

Licks 笔记是 Markdown，会按链接类型预览（`web/licks.js` 的 `licksBilibiliId` / `licksIsAudioUrl` / `licksIsPdfUrl`）：

| 想放的东西 | 写法 | 效果 |
|---|---|---|
| B 站视频 | `[标题](https://www.bilibili.com/video/BV1PH4y1N7Vr/)`，可加 `?p=2` 选分 P | 缩略图，点击后换成 B 站播放器（有声音、有原画面） |
| 音频（`mp3 / wav / m4a / ogg / flac`） | 材料库上传后插入，或 `[名字](/api/materials/xxx.m4a)` | 迷你播放器：播放/暂停、拖动进度、变速（变速记住每个文件） |
| 谱子 PDF | 材料库上传后插入，写成 `[名字](url "page=1")` | 内嵌 pdf.js 查看器，可批注并存回服务器 |
| 本地视频（`mp4 / webm / mov / m4v`） | 材料库上传后插入（上传框放开了 `video/*`，视频上限 1GB，音频/PDF 仍是 100MB） | 笔记里直接内嵌浏览器自带的 `<video controls>`（有声音、可拖进度、⋮ 菜单里变速；拖进度走 Range 请求，不会整段下载） |

**跳到视频的某个时间（章节）**：笔记里写 `[第一句 3:46](/api/materials/xxx.mp4#t=226)`，点击后让页面里这个视频跳到 226 秒并播放，不会再开一个播放器。
时间可以写秒数或 `m:ss`；`#t=3:46,11:00` 表示 3:46 到 11:00，播到结尾自动停（手动拖动进度条会取消自动停）。
页面里没有这个视频的播放器时，链接会在新标签页打开，浏览器自己按 `#t=` 定位。
B 站视频自带的章节（yt-dlp 的 `%(chapters)j` 能读到起止时间）可以直接转成这样的一行链接贴在视频下面。

注意：B 站是音视频分开存的，只下画面（`-f 30080`）得到的 mp4 **没有声音**，放进 Licks 前要先和音频（`-f 30280`）合并。
本地视频的变速没有做"按文件记住"（音频迷你播放器有），也没有接 App 的输出设备选择和主音量，这两项还没做。
只想留声音反复变速听，仍可以把音频抽成 m4a（`ffmpeg -i x.mp4 -vn -c copy x.m4a`，不重编码）上传。

## 已知限制 / 还没验证

- 跑过两个视频。第二个（野蜂飞舞，B 站 `BV17pPMz5Emk`）谱条在画面**顶部**，开头约 70 秒快速翻页（每页 2.5 秒、约 6 小节、相邻页重叠 ~900px）：
  `video_pages.py VIDEO OUT 2 0 310` 取页，只拷贝前 28 页（后面是第二遍慢速）到新目录并截断 `pages.json`，
  再 `FIXED_STAFF=89.5,23.2 MINN=3 MAXOV=2500 video_tab.py`（页停留帧数少 → `MINN`；密集页遮住谱线 → `FIXED_STAFF` 固定谱线；最后一页重叠大 → `MAXOV`），最后 `compose_rows.py`。
  结果 107 小节 27 行。左侧 TAB 谱号下会带一小段符杠残留，未处理。
- 第三个（Together Again，`BV1YW42197f5`）：谱条在画面下半部分，含简谱；`video_pages.py VIDEO OUT 4 700 380`（起点必须避开上方的吉他画面，否则"顶部漏画面"逻辑会把简谱数字当漏画面抹掉），再 `MAXOV=2500 video_tab.py`。
- 第四个（The Thrill Is Gone，`BV1wT4y1d72H`）：谱不在演奏画面里，而是视频最后 12 秒的 3 张整页谱（720p，已经是每行 4 小节的排版）。直接截 3 帧、裁掉黑边、放大 4 倍存成 PDF 即可，不需要拼接。先看视频末尾有没有整页谱。
- 第五个（《后来》，`BV1Fv4y1g7jG`）：谱条在底部且是**半透明蓝灰底**（纸色约 212 而不是白），左下角有 B 站水印会遮住符干。
  对脚本做的通用改动：`video_pages.py` 按每帧中位数自动识别纸色并归一化到 255；`video_tab.py` 谱线检测多档阈值重试、失败的页借用其他页的谱线几何（不再需要 `FIXED_STAFF`）；
  配准可用 `REG_BELOW=8` 排除谱线下方的水印区；重叠区配准良好（ncc≥0.8，`MERGE_MIN_NCC`）时取更暗的像素，用另一页补回被水印盖住的音符，较差时退回中缝切换（取暗会让错位 1~2px 的数字重影）；
  大重叠（~2600px，页几乎一样）ncc 只有 0.6，用 `MIN_NCC=0.55 MAXOV=2780` 才认；TAB 谱号裁剪去掉谱线下方（水印碎片）。
  最后两页是曲子循环重播，和前页重叠几乎整页。第 1 页左下的水印盖住了第 1 小节的符干，没有别的页能补，会留一点残影。
- 一条龙入口：`experiments/tab-stitch/scripts/video_to_score.sh`（出 PDF）+ `publish_lick.py`（上传并建 Lick），流程写在项目 skill `video-tab-to-lick`。
- 宽度 1920 仍写死；看着像"滚动"的视频先用相位相关测位移，位移几乎全是 0 就是翻页。
- 小节号不识别；跳着讲的视频顺序可能错。
- 每首曲子的"异常情况"（小节线漏检、重叠太小、水印位置）要多做几首才能见全，所以脚本是实验性质，不追求通用。
