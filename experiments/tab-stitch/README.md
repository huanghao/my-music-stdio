# tab-stitch：把大小不一的吉他谱截图拼成整齐的谱子

首次实验（2026-11）：用户从视频里手动截了 11 张 solo 谱截图（`1-5.png`…`44-48.png`，TAB 谱，48 小节），
要求拼成"每行 4 小节"的 PDF。这里记录做法、踩过的坑和脚本，下次做另一首时少走弯路。
脚本是一次性的、不追求通用：每首曲子的几张**手工表**要重新填（见下）。

内容全部来自截图原像素，**没有做 OMR（识谱）**，所以音符不会错，但被水印盖住的像素恢复不了。

## 流程（脚本对应）

| 步骤 | 做什么 | 脚本 |
|---|---|---|
| 1 | 找谱线：行方向上超过 60% 宽度偏暗的行 = 谱线（6 线 TAB）。算谱线间距 `sp` | `analyze.py` |
| 2 | 统一缩放：每张图缩放到 `sp = 32px`，第 1 线对齐到固定 y（`TOP=175`），画布补背景色 | `norm.py` |
| 3 | 找小节线：谱线区内某列 ≥93% 是深色，且谱线下方**没有**墨迹（符干会延伸到谱线下方，小节线不会） | `bars.py` |
| 4 | 对被截断的小节：用相邻两张图的重叠区做相关性（NCC）找位移 | `reg.py`，`reg2.py`（带缩放容差） |
| 5 | 每个小节切成 `[左小节线-PAD, 右小节线+PAD]`；被截断的按位移拼接 | `stitch.py` |
| 6 | 擦水印、拼 48 个小节、每 4 个一行 | `build.py` |
| 7 | 行对齐（两端对齐）、排进 A4 横向 PDF | `final2.py` |

运行时数据放 `~/workspace/my-store/tab-stitch-data/`（不要写进仓库）：

```bash
cd ~/workspace/my-store/tab-stitch-data
PYTHONPATH=~/workspace/my-music-stdio/experiments/tab-stitch/scripts python3 -s <脚本>.py
```

- 用 `python3 -s` + `PYTHONPATH`，不要用 `-I`（`-I` 会把脚本目录也去掉，`import norm` 会失败）。
- 只依赖 numpy / scipy / Pillow。机器上没有 opencv、reportlab、ffmpeg、tesseract；PDF 直接用 Pillow 保存。
- 脚本里路径写死了（`~/Downloads/`、输出到 `~/Downloads/guitar-solo-tab.pdf`），换曲子要改。

## 每首曲子要手工填的表

1. `norm.py` 的 `LINES`：每张图第 1 线和第 6 线的 y（`analyze.py` 的输出；注意有异常行，如底部蓝色进度条会被当成谱线，要人工剔除）。
2. `stitch.py` 的 `BARS`：每张图里每条小节线的 x 和小节号（`bars.py` 检测 + 看图校对）。
3. `stitch.py` 的 `OVERLAP`：相邻图的重叠像素（`reg.py` 的输出；负数 = 没有重叠，中间留空白）。
4. `build.py` 的 `WM`：水印框坐标。

## 关键逻辑 / 踩过的坑

- **每张图缩放比例不同**（谱线间距 27~37px），必须先归一化。拼接时个别图还要再微调缩放（`21-25` 需要 ×1.02 才对上）——用 `reg2.py` 的缩放容差搜索。
- **截图常常切在小节中间，重叠很小（40~130px）甚至没有**。没重叠时 NCC 的最高点会落在"重叠最小"的位置，是假峰值，要看图确认。没有重叠的情况下我留了估计宽度的空白；之后用户确认该小节是 4 拍、中间只是长音的空白，没有漏内容。判断有没有漏内容可以数拍子。
- **小节线漏检**：带圈音（尾音）的符干在第 1 线上，会和小节线连成一条，`below` 条件把它判掉（`29-33` 的第 33 小节线就是手工补的）。
- **小节号标签居中在小节线上**（谱线上方），切小节时若在小节线处硬切会把数字切成两半。解决：每个小节左右各多切 `PAD=20px`，相邻小节在共享小节线处对齐，重叠区用 `np.minimum` 合并（墨迹取并集），数字和小节线都完整，也不会重影。
- **相关性对齐时要把谱线下方（符杠区、水印区）屏蔽掉**，只比谱线以上的部分。
- **水印**（B 站播放器的半透明白色圆角方块，约 107×107px）：底色比背景亮（253 vs 244），盖住的墨迹基本丢失。处理：框内灰度 ≥110 的像素改回背景色，再把被盖住的谱线补回来（取框外相邻列的行中位数）。框内残留的墨迹碎片（播放三角处）会留下一点瑕疵。
- **行对齐**：第一版只统一了谱线大小，右边参差不齐，用户一眼就看出来。第二版两端对齐：
  找"除谱线外整列都没有墨迹"的空白列（做 ±5px 膨胀避免贴着音符），把额外宽度按空白段长度比例分配，复制空白列加宽；字符不拉伸。
  比目标宽度 `T=2800` 还宽的行整体缩小（最多约 13%）。节奏稀疏的行会被拉得比较开，属于预期。
- **字体**：PIL 画中文用 `/System/Library/Fonts/STHeiti Medium.ttc`；PingFang.ttc 直接用会显示成方块。
- 总结时别说"对齐了"除非真的看过输出图——这次第一版我只做了谱线大小统一，措辞含糊，被用户指出。

## 视频输入：已跑通（`video_*.py`、`compose_rows.py`）

用户给了 B 站视频（`BV1PH4y1N7Vr`，《At The Place Where You Call》带谱教学，38 分钟，1080p）。
从视频直接生成了和手工截图版内容一致的 48 小节谱子，全程自动，没有手填任何表。

```bash
cd ~/workspace/my-store/tab-stitch-data
S=~/workspace/my-music-stdio/experiments/tab-stitch/scripts
yt-dlp --cookies-from-browser chrome -f 30080 -o "video/%(id)s.%(ext)s" "<url>"   # 1080p 纯视频流，够用
python3 -s $S/video_pages.py video/<id>.mp4 pages 2        # 约 1 分钟：逐帧读谱区 → 按"页"分组
python3 -s $S/video_tab.py pages pano                      # 约 3 分钟：去重、归一化、对齐、找小节线
python3 -s $S/compose_rows.py pano ~/Downloads/out.pdf     # 每行 4 小节、两端对齐、PDF
```

### 视频的特点（这个视频，换视频要重新确认）
- 谱区是画面下半部分（y≥592 的白色条），**没有 B 站水印**（水印只出现在用户自己的截图里，视频本身没有）。
- 谱面是**翻页**，不是平滑滚动：一页大约 4~5 个小节，相邻页只重叠半个小节左右（所以用户的手工截图拼起来也是这个难度）。
- **每页缩放比例不同**（谱线间距 21~28px，播放器按页面内容自适应），同一页的垂直位置也会变（上方标注越高谱线越靠下）。所以要和手工版一样，先按谱线间距归一化。
- 一个蓝色半透明**播放头**在页面上扫过。同一页会显示几十秒，逐像素取 max 就能去掉（未被盖住的纸面更亮）。同页重复出现（老师反复讲同一段）的帧再合并一次，残留也会消失。
- 部分页面的上端会漏进吉他画面和字幕（谱区最上面约 56px）：比较内容时忽略这一段，页面里顶端平均亮度低于 225 就把它涂白（谱面的拨弦记号都在更下面）。

### 流程细节
1. `video_pages.py`：ffmpeg 管道输出灰度裸帧（2fps），谱区需要 60% 以上像素是浅色才算有谱；与上一帧的墨迹差异 >25% 视为翻页；每页取逐像素 max。
2. `video_tab.py`：
   - **去重**：重复的页比较墨迹时要**容忍 1~2px 垂直抖动**（膨胀 2 次再比较）。只用 XOR 比较时，同一页因为上下偏了 1px 差异就有 20%，会被当成新页，后面的拼接就乱了。
   - **找谱线**：行方向 >55% 偏暗的行，再在这些候选中找"6 条间距均匀"的组合（有的页还会混入三连音括号线、字幕残留）；用 `polyfit` 拟合间距和起点。
   - **对齐**：与手工版相同的 NCC，另加 ±3% 的缩放微调；相邻页匹配度 <0.7 视为没有重叠，插入固定宽度的空白（`GAP=120`），并在日志里提示人工检查。本视频里只有第 17 小节这一处，和手工版一致，用户确认过那里没有漏内容。
   - 小节线：和手工版同一个判据；相距 14px 以内的合并（终止线是粗细双线）。本视频检出 49 条 = 48 小节 + 1。
3. `compose_rows.py`：和 `final2.py` 的排版逻辑一致（4 小节一行，空白列加宽两端对齐，行宽超过 T 的整体缩小）。

### 换一个视频时要先确认的
- 谱区位置（`video_pages.py` 的 `y0`、`h` 参数）和宽度（`W=1920` 写死）。
- 谱面是否翻页；如果是平滑滚动，页面会被切得很碎，`video_tab.py` 的去重/相邻对齐要改成连续拼接。
- 视频里的标注/播放头颜色、水印位置。
- 小节号标签没有做 OCR，小节顺序靠"按时间顺序的首次出现 + 相邻页对齐"推出来。如果老师在视频里跳着讲（先讲后面再回头），顺序可能不对，要看日志里的 NCC 和页号。
